# Web UI/UX review

## Outcome

**The app has a consistent visual base, but its main tasks are not consistently
clear at a glance.** Keep the Radix components, teal accent, visible labels, and
state feedback. Improve content order and action emphasis before adding design
features or explanatory text.

The main changes to consider are:

1. Put the exercise name and history before the metadata editor.
2. Put recorded sets first on completed workouts. Make **Complete set** the main action during training.
3. Make exercise filters work as one task without clearing other selections.
4. Reduce the controls and summary content before workout history on mobile.
5. Make existing training actions available beside their source workout or template, not inside schedule configuration.

This is a review and implementation handoff, not a UI redesign. No application,
API, schema, production setting, or stored user data was changed.

**Human validation is not complete.** No participant results, screen-reader
results, or one-second comprehension pass are claimed. The goal of an app that
users understand in one second remains unverified.

- Additional layout measurements: 320 CSS-pixel width for the 14 signed-in route/state samples in both locales.
- Real 200% browser zoom: 36 samples in isolated persistent Chrome profiles. Chrome's Page zoom setting is set to 200%; assertions require devicePixelRatio 2 and a 720 × 406 CSS viewport from a 1440 × 900 window. CDP captures the full physical viewport, with a PNG-width assertion to prevent native-zoom clipping.
- Fixtures: a real first-run administrator created through setup; separate regular, empty-history, and administrator accounts; one shared bilingual exercise; 24 completed workouts and one active workout; a template; three measurements and a target weight. The active workout is also inspected after pausing.
- Data is synthetic. Passwords are bcrypt hashes. Database files are disposable runner-owned SQLite files. Screenshots and DOM inventories do not include password values or session tokens.

The tree groups information; it does not imply account or administration landing
pages. Those pages do not exist and are not proposed here.

## Prioritized findings and acceptance criteria

No Critical or High defect is established by this review. Medium design findings
below are based on rendered facts plus expert judgment; user impact must be
validated with participants. The filter-reset finding is directly reproduced
behavior. Proposed owners are **unassigned**; fixes are separate authorized work.

### U01 — Medium: exercise identity comes after configuration

- Affects: `/exercises/:id`, owner and non-owner states.
- Reproduce: open a creator-owned exercise at 390 × 844 with the audit fixture.
- Observed: the entire first viewport shows metadata selection; the H1 begins at about y=1227. Even non-owners see metadata before the exercise name.
- Expected: users can identify the exercise before editing its tags.
- Impact: first attention goes to maintenance rather than the history task. Whether this causes task failure is not yet user-tested.
- Evidence: P `exercise-en-390.png`, `exercise-zh-TW-390.png`, inventories; S `pages/exercise.tsx:52`, `components/exercise-metadata.tsx:29`.
- Correction: **defer** expanded edit controls; **retain** a compact read-only metadata summary.
- Acceptance: H1 precedes metadata/edit controls in DOM and visual order for all roles. Records/history precede collapsed editors. Opening/saving editors retains values, ownership checks, and duplicate feedback in both locales.

### U02 — Medium: training does not emphasize completing the current set

- Affects: active/paused `/workouts/:id`.
- Reproduce: open the three-set active fixture at 390 × 844.
- Observed: session controls come first; RIR and notes precede equally solid Save and Complete set controls. First-set completion is below the initial viewport.
- Expected: actual-value entry and the next set action form the main task.
- Impact: optional detail competes with the frequent logging action; no human error rate is established.
- Evidence: P `active-*`, `paused-en-390`; S `components/session-panel.tsx:162` and existing `ux-findings.spec.ts`.
- Correction: **retain** weight/reps and state; **defer** optional fields; **restyle** Save as secondary and Complete set as primary.
- Acceptance: common current-set input and completion form one clear group, with a single dominant action. Zero-weight actuals, keyboard operation, save-only intent, pause/resume, conflict recovery, and finish/abandon confirmations remain verified. Test the resulting hierarchy with participants.

### U03 — Medium: completed workout starts with new-session tools

- Affects: completed `/workouts/:id`.
- Reproduce: open the completed long-title fixture on mobile.
- Observed: Start training precedes the recorded summary; editing and template forms precede Sets, around y=2348 in the fixture.
- Expected: a recorded workout opens with its recorded result.
- Impact: users must pass several unrelated actions before inspecting sets.
- Evidence: P `completed-*`, full-page capture; S `pages/workout.tsx:91`.
- Correction: **reorder** recorded content first; **defer** metadata, template, and reuse forms.
- Acceptance: recorded sets follow title/date and compact result information; expanded configuration no longer precedes them. Add/edit/delete, repeat, template saving, and starting a new session remain available and distinguishable.

### U04 — Medium: mobile task content is below summaries and filters

- Affects: shared signed-in shell, populated `/workouts`, `/exercises`.
- Reproduce: view populated Workouts at 390 × 844.
- Observed: header occupies about 228 pixels; summaries and expanded filters follow. First workout title starts around y=986. Exercise metadata filters appear before search.
- Expected: the common task is visible before optional analysis/filtering.
- Impact: the opening view emphasizes setup controls rather than useful results. Header height alone is not a defect; the combined content order is the concern.
- Evidence: P `workouts-en-390.png`, `exercises-en-390.png`, corresponding Chinese views and inventories.
- Correction: **retain** labeled navigation and search; **defer** less-used filters/summary detail; **combine** repeated counts.
- Acceptance: opening mobile views show relevant history/library content or a clear empty state without expanding optional controls. Active filtering is summarized and clearable. Do not remove utility destinations, units, state labels, or 20-row pagination.

### U05 — Medium: template training is under schedule configuration

- Affects: `/workouts`, template/live-training entry.
- Reproduce: inspect a template in Workouts, then expand Weekly template schedule.
- Observed: the template card offers retrospective creation; Start training is under the schedule disclosure, after seven schedule forms in source order.
- Expected: starting from a template is associated with the template, not weekly configuration.
- Impact: users must know where to look for an existing feature. Participant discoverability is unverified.
- Evidence: S `pages/workouts.tsx:405`, `components/template-planning.tsx:41` and `:72`; B `ui-roadmap.spec.ts` uses this disclosure to start training.
- Correction: **move** the existing start action beside its template; **defer** scheduling/progression.
- Acceptance: users can find Start training from a template without opening schedule settings. Logging a past workout remains a separate labeled action. Do not decide the app-wide dominant task without user evidence.

### U06 — Medium: exercise filter forms clear each other's selections

- Affects: `/exercises`.
- Reproduce: open `/exercises?q=Bench&sort=recent&muscle=chest&equipment=barbell`. Submit metadata filters, then repeat the initial URL and submit search/sort.
- Observed: metadata submit produces `?q=Bench&muscle=chest&equipment=barbell`, dropping sort. Search submit produces `?q=Bench&sort=recent`, dropping muscle/equipment.
- Expected: changing one filter preserves the other selected criteria.
- Impact: results and selected criteria change unexpectedly during a single find-exercise task.
- Evidence: P JSON entries `metadata-submit-drops-sort` and `search-submit-drops-metadata`; S `pages/exercises.tsx:105`, `:143`, and `components/action-form.tsx` query replacement.
- Correction: **combine** filter submissions or explicitly preserve all criteria.
- Acceptance: q, sort, muscle, and equipment survive changing/applying any one criterion; reload and back/forward preserve the intended state. Muscle and Equipment have visible labels or distinct All muscles / All equipment defaults, not only accessible names. Replace the audit's defect-reproduction assertions with desired-contract regression tests after a separately authorized fix.

### U07 — Medium: source instructions have no source links

- Affects: `/source`.
- Reproduce: visit while signed out or signed in.
- Observed: the paragraph says to see the repository and LICENSE file; the main content contains no links.
- Expected: direct access to the named material.
- Impact: users cannot perform the stated next step from the page without locating the repository elsewhere.
- Evidence: G/P `*source-*`; S `pages/source.tsx`, `lib/messages.ts:291`.
- Correction: **replace** indirect instructions with named links; **retain** the license identifier.
- Acceptance: accessible Repository and License links work for both authentication states and locales. No extra explanation is required to find them.

### U08 — Medium: missing outcomes do not provide useful local recovery

- Affects: `*`, missing/foreign record outcomes, Routing group.
- Reproduce: open `/review-missing` or a missing/foreign workout.
- Observed: fallback has only alert text; record errors offer Try again as the only content action. No H1 is provided.
- Expected: a clear unavailable-page state with a path to a valid destination.
- Impact: retrying a permanent missing record does not help the user leave that state.
- Evidence: G/P missing captures; S `app.tsx` `MissingPage` and `PageBoundary`.
- Correction: **retain** distinct status messages; **replace** the dominant retry with relevant navigation for permanent outcomes.
- Acceptance: keyboard/screen-reader users receive an appropriate heading and can reach login or Workouts through a named local link. Transient read failures still have retry; 401 still clears private state rather than masquerading as 404.

### U09 — Medium: measurement entry and target actions are indistinguishable

- Affects: `/measurements`.
- Reproduce: open populated or empty Measurements.
- Observed: two stacked forms each have a solid Save action; a rules paragraph precedes both.
- Expected: the frequent measurement task has clear emphasis and task-specific feedback/actions.
- Impact: users must read surrounding fields to distinguish identical actions.
- Evidence: P `measurements-*`, `empty-measurements-*`; S `pages/measurements.tsx`.
- Correction: **rename** actions by task, **defer** target editing, **relocate** replacement guidance beside the date.
- Acceptance: Save measurement and Save target have distinct localized visible/accessibility labels; same-date replacement and units remain explicit; clearing a target never removes measurement history.

### U10 — Low: secondary text and actions add avoidable competition

- Affects: Public, Account, setup/login, workout creation/empty history, Calendar, Stats, exercise empty history, Data.
- Reproduce: inspect the corresponding G/P captures and source structures.
- Observed: repeated generic introductions/empty-state prose, equal login-method emphasis, duplicated calendar creation context, six pre-chart Stats metrics, two plain account cross-links, multiple Data action stages, and empty-record summary cards.
- Expected: purpose → useful content/input → next action → secondary detail.

## Independent review and corrections

Two visual-review subagents assessed the captured core and supporting pages
before comparing their observations with this report. Both supported preserving
the visual theme and changing content/action order first. Their additional
findings were checked against screenshots and source: visible filter labels,
point-of-use units (U15), disabled Preview styling (U16), and the measurement

completed-only and not identical to the grid/day collection.

cleanup that depended on successful evidence writes, unguarded full-page
captures, overstated bootstrap/cancellation coverage, an inconsistent checked
journey item, and missing live-participant provisioning/scoring. Fixtures and
capture readiness were corrected; bootstrap received a dedicated test; the
journey item was reopened; the participant guide now has an opt-in disposable
session and predefined core scoring. Unperformed cancellation and manual checks
remain explicit limitations, not inferred passes.

assertion. Setting Page zoom through Chrome settings succeeded. Review of the
images then exposed Playwright's native-zoom clipping; direct CDP capture plus a
PNG-width assertion corrected it. The final focused audit passed after these
corrections. Earlier failed/cropped attempts are not the final visual evidence.

Subagents are expert reviewers. Their agreement is not human participant data
and does not establish the one-second target.
